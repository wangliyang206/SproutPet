## 〇、三层真相源与核对方法

| 层 | 真相源 | 怎么算"对上了" |
|---|---|---|
| **L1 产品** | [`00-产品需求文档PRD.md`](./00-产品需求文档PRD.md)（v3.2）+ [`14`](./14-首日体验与孵化节奏.md) / [`15`](./15-宠物形象规范.md) | 每条口径有一个可判定的句子 |
| **L2 设计** | `design-v2/gen.py` 的 `SCREENS`（**31 屏**）+ 归档页（资料库 node `w0E0zFOVV7v18SLWKceyq9` · **v2.12**） | 每个屏有编号、有出处、有"旧稿怎么处理" |
| **L6 代码** | `app/src/main/java/**` 与 `app/src/main/res/layout/**` | 能指出**具体文件**承接了那一屏 |

**判定口径（三档）**：

- ✅ **一致** —— 产品有口径、设计有屏、代码有落点。
- 🟡 **部分** —— 有落点但缺关键要素（缺入口 / 缺一类功能 / 形态与设计不符）。
- ❌ **缺位** —— 设计有屏、产品有要求，代码里**找不到对应实现**。

> ⚠️ **不做的事**：本文不评判"该不该做"，只回答"现在是不是同一件事"。
> 该不该做、什么时候做，看 [`04-开发计划`](./04-开发计划.md) 与 [`12-阶段闸门`](./12-阶段闸门与冻结基线.md)。

## 一、结论摘要（2026-10-20 复核）

| 状态 | 屏数 | 占比 | 相比 v1.0 |
|---|---:|---:|---|
| ✅ 一致 | **13** | 42% | +8（十连 / 融合 / 配对 / 19 隐私门 / 20 图鉴 / **03 托盘 / 04 揭晓**） |

| ❌ 缺位 | **10** | 32% | −12 |

**一句话结论**：**L1 与 L2 高度自洽（31 屏逐屏有 PRD 出处），断点全在 L6** ——
代码覆盖「场景壳 + 首蛋 + 起名 + 抚摸 + 仓店 + **抽蛋/十连/融合/配对** + **隐私门/图鉴/族谱/浮卡**」这条竖切，**其余 12 屏仍是空的**。
⭐ **口径冲突 6 处已全部闭合（v1.6）** —— 最后两处 `K-2`（互动托盘）/ `K-5`（揭晓底部升起）已于 2026-10-20 落地。
这类比缺位更危险：缺位看得见，**"文档说了、代码不是那样"看不见** —— 本表的 §三 从此清空，新冲突按 §六 维护规则登记。

## 六、维护规则

1. **任何一次"补上了某屏"**，必须在 §二 把该行状态改为 ✅，并在 §四 追加一行（改了哪些文件、哪条测试守住）。
2. **任何一次"改了产品口径"**，先回填 §三 —— 只改 PRD 不改这张表，等于又制造一处口径漂移。
3. 状态从 ✅ 退回 🟡/❌（例如重构删了入口）也算变更，必须记录，**不许只改代码**。
4. 屏数变化（31 → N）时，§二 表必须同步增删行，并更新 `02 §十一` 对照表与本文件头部版本。
5. 本表**不重复抄需求**：口径写在 `00` / `14` / `15`，这里只留"对上没对上"。
6. ⭐ **"代码落点"一列必须是可 `grep` 到的真实文件**（2026-10-20 核对新增）。
   不许写"应该有"的类名 —— 本次核对一次抓出 **8 个在代码里根本不存在的名字**

   `HomeViewModel` / `fragment_home.xml` / `SceneEggView` / `NpcPetGenerator`）。
   ⚠️ 更隐蔽的是**名字存在但没人调用**（`PetFloatingService` 43 行空壳、
   5 个互动 UseCase 零调用方）—— 状态列写 ✅ 之前，必须确认**有消费者**，否则最多 🟡。
