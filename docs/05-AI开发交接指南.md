## 一、30 秒了解项目

**萌芽宠物 SproutPet** 是一款 Android 养成类 App。

- **核心玩法**：领盲盒蛋 → 孵化 → 破壳出幼崽 → 互动养成 → **配对生育**（真人/NPC）→ 族谱；宠物还会**上桌面**陪伴，并在家庭情景中互相反应
- **物种体系**：**五虫**（蠃鳞毛羽昆）+「不入十类之种」，共 **18 种 / 6 类群**
- **稀有度**：**6 档**（普通 / 稀有 / 史诗 / 传说 / 神话 + **灵兽**）。灵兽不可抽取、仅遗传产生，并配套**灵血传承**（隐性印记 0~3，可隔代觉醒，见 §6.2.2）
- **技术栈**：Kotlin + XML + MVVM + Hilt + Room + Retrofit + **Rive（宠物渲染）**
- **工程位置**：`E:\git\SproutPet`
- **包名**：`com.sproutpet.pet`
- **架构**：`app`（UI）+ `core`（领域/数据/基础设施）双模块

### 6.2 稀有度（6 档 ⭐）

```kotlin
enum class Rarity(val id: Int, val displayName: String, ...) {
    COMMON(0, "普通"), RARE(1, "稀有"), EPIC(2, "史诗"),
    LEGENDARY(3, "传说"), MYTHIC(4, "神话"),
    MUTANT(5, "灵兽"),   // ⭐ v2.1 新增，weight=0，不可抽取（灵血浓度见 ExoticBloodRules）
}
```

影响：开出概率、成长系数、孵化时长、外观特效、遗传概率。

**⭐ 最重要的三条规则**

1. **`MUTANT`（灵兽）永不进抽取池**。所有抽取路径必须用 `Rarity.drawableEntries()`（会过滤 `isDrawable=false`），**不要用 `Rarity.entries`**。灵兽只能由 `BreedingRules.offspringRarity`（含灵血觉醒）遗传产生，异兽物种只能由 `offspringSpecies` 产生。**这两件事必须分清。**
2. **任何"保底 / 指定稀有度"能力，都必须用 `Rarity.maxDrawable` 钳制上限**（⭐ v1.2 新增）。否则一张"灵兽保底券"就能绕开 ADR-017。`BlindBoxEngine.draw` 已内置该钳制，新增同类能力时请照做 —— `BlindBoxEngineTest` 有断言守住。
3. **遗传是"概率漂移，不降级"**：以 `max(父母稀有度)` 为基准做加权漂移，**永不跌破基准**。这保证用户投入不被背叛，同时保留上漂惊喜。

### 6.2.1 物种体系：五虫（⭐ v2.1 核心）

```kotlin
enum class SpeciesFamily(
    val deity: String,
    val definition: String,
    val deityId: Int?          // ⭐ v2.4：神兽形态渲染通道，0蛟龙 1麒麟 2凤凰 3神龟；蠃虫/不入十类为 null
) {
    LUO("圣人", "蠃虫 · 无鳞无甲无羽无毛者", deityId = null),
    LIN("蛟龙", "鳞虫 · 有鳞者", deityId = 0),
    MAO("麒麟", "毛虫 · 有毛者", deityId = 1),
    YU("凤凰", "羽虫 · 有羽者", deityId = 2),
    KUN("神龟", "昆虫 · 有甲者", deityId = 3),
    UNCATEGORIZED("—", "不入十类之种", deityId = null),   // 异兽类，不可抽取
}
```

**分类依据**：《西游记》第五十八回如来原话 ——「周天之内有五虫，乃蠃、鳞、毛、羽、昆」。

> 中国神话体系中的神兽、异兽**本就内含于五虫**：五虫之"长"即**神兽**（凤凰 / 麒麟 / 蛟龙 / 神龟 / 圣人），而"不入十类之种"（如混世四猴）即**异兽**。
>
> ⚠️ **术语区分**：本项目另将「**灵兽**」一词**专用于稀有度第 6 档**，与上述"神兽""异兽"不是一回事。
> 三者互不蕴含 —— 星狐（异兽）可以是普通稀有度，懒猫也可以是灵兽。见 §6.2 与 06 §三 表注。

**规模**：**18 种物种 / 6 类群**，每类群 3 种。详见 [07-五虫体系设计](./07-五虫体系设计.md)。

```kotlin
object PetSpecies {
    val FIVE_WORMS: List<SpeciesFamily>   // 蠃鳞毛羽昆，顺序即如来原话顺序
    // 每族 3 种：蠃虫 SNAIL/BUBBLE_FROG/SOFT_OCTOPUS，鳞虫 KOI/GRASS_SNAKE/LITTLE_DRAGON ...
}
```

**⚠️ 三条不可违反的红线**

1. **`SpeciesFamily` 枚举本体只有 6 个值**。历史别名（`BIRD`/`MAMMAL`/`OVINE`/`FELINE`/`EXOTIC`）**只能存在于 `fromName()` 字符串映射里**，绝不可写成枚举常量。枚举常量是独立条目不是别名，混入会污染 `entries` → 任何遍历类群的 UI 出现幽灵项。已有测试守住。
2. **类群不落库**，由 `species.family` 派生，避免双重真相源。
3. **跨虫上漂系数必须 > 同虫**（`1.0 < 1.35 < 1.8 < 2.0`）。这是**刻意设计**，用数值奖励跨虫社交；反转会直接摧毁社交生态。已有测试守住。

**⭐ 两条已决策的边界（不要越界）**

| 决策 | 结论 | 在代码里怎么体现 |
|------|------|-----------------|
| | **ADR-020** | 蠃虫之长「圣人」**不做形象** | `SpeciesFamily.LUO.hasDeityForm == false`、`deityId == null`（其余四虫为 `true` / `0~3`）。**禁止**在 `deity/` 下加蠃虫层，也禁止加替代品 |
| | **ADR-021** | 五虫**不影响属性数值** | `PetAttributes.ofLevel(level, rarity, tendency)` —— **不接收** `SpeciesFamily`。各物种 `tendency` 已跨类群打散，避免类群间接入数值 |
| ⭐ | **ADR-026** | 完整神兽形态层由**「灵兽 × 同虫」独占** | `DeityRules.hasFullDeityForm(rarity, family, pairingKind)`。⚠️ 判定需要"诞生时的配对类型"，所以结果**必须落库**（`pet.deity_form`），不能渲染时现算 |

**❓ 那五虫靠什么让玩家在乎？**（这是新人最常问的）

| 手段 | 说明 |
|------|------|
| 配对加成 | 跨虫上漂 1.35 > 同虫 1.0 —— 用**遗传概率**而非属性奖励跨虫 |
| 图鉴收集 | 按蠃鳞毛羽昆分页，集齐一类有称号（纯荣誉） |
| 身份标识 | 族谱图例按五虫分色，宠物卡面显示虫属 |
| 神兽形态 | 四虫各有其长，是外观的终极目标 |
| 叙事文案 | 直接从典籍取词，文学性本身就是价值 |

> 📖 完整论证见 [07-五虫体系设计](./07-五虫体系设计.md) §9之一。

### 6.2.2 灵血传承（⭐ v1.2 新增）

**解决的问题**：灵兽只能靠生育，而生育有 10% 概率回落到神话档。没有补偿机制时，**一次回落就永久断代** —— 玩家辛苦养的灵兽血统会在孙辈彻底消失。

**灵血**（`Pet.exoticBlood`，取值 0~3）是灵兽血统的**隐性印记**：

| 情形 | 后代灵血 |
|------|---------|
| 后代是灵兽 | 满值 `MAX_BLOOD`（3） |
| 后代不是灵兽，但父母携带灵血 | 父母中较高者 **− 1** |
| 父母均无灵血 | 0（且不可能觉醒） |

后代**最终不是灵兽**时，还有一次**觉醒判定**：灵血 1 / 2 / 3 → **3% / 8% / 15%**。命中则直接跃升为灵兽，灵血回满。

```kotlin
object ExoticBloodRules {
    const val MAX_BLOOD = 3
    fun awakenRateOf(blood: Int): Float
    fun carrierBloodOf(bloodA: Int, bloodB: Int): Int
    fun inheritedBlood(carrierBlood: Int, offspringIsExoticBeast: Boolean): Int
    fun shouldAwaken(carrierBlood: Int, random: Random): Boolean
}

// 完整推导入口（三步顺序不可调换：概率漂移 → 灵血觉醒 → 冷启动保底）
GrowthRules.BreedingRules.resolveOffspringRarity(
    parentA: Rarity, bloodA: Int,
    parentB: Rarity, bloodB: Int,
    kind: PairingKind,
    pityFailStreak: Int = 0,     // 账号级连败计数，0 即等价于关闭保底
    random: Random
): OffspringRarityResult   // → rarity + exoticBlood + awakened + pityTriggered
```

> ⚠️ **红线**：灵血**只影响觉醒概率，绝不参与属性计算**（守住 ADR-021）。
> `ExoticBloodRulesTest` 有断言守住：`blood never affects attributes`。

> 💡 灵血是**叙事资产**，不是数值系统。它让"我的家族出过灵兽"在后代身上留下痕迹，族谱可展示"第 N 代 · 灵血 2 级"。

### 6.2.3 神兽形态（⭐ v2.4 变更：ADR-026）

**形态分两层，取值来源完全不同 —— 这是最容易接错的地方：**

| 层 | 判定 | 来源 | 是否落库 |
|----|------|------|---------|
| **神兽特征层** | 稀有度 ≥ 传说 | `DeityRules.hasDeityFeatures(rarity, family)` | ❌ 纯推导 |
| **完整神兽形态层** | **灵兽 × 同虫** | `Pet.hasFullDeityForm`（出生时 `DeityRules.resolveAtBirth` 结算） | ✅ `pet.deity_form` |

```kotlin
object DeityRules {
    fun hasDeityFeatures(rarity: Rarity, family: SpeciesFamily): Boolean
    fun hasFullDeityForm(rarity: Rarity, family: SpeciesFamily, pairingKind: PairingKind?): Boolean
    fun deityIdOf(family: SpeciesFamily): Int?          // 0蛟龙 1麒麟 2凤凰 3神龟
    fun resolveAtBirth(rarity: Rarity, species: PetSpecies, pairingKind: PairingKind?): Boolean
}
```

> ⚠️ **为什么必须落库**：判定需要"诞生时的配对类型"，而宠物自身**推不出来**
> （`parentIdA/B` 只指向父母）。这是 `exotic_blood` 事故的同类问题，
> 这次已一次性补齐（列 + 迁移 + 双向映射 + 往返测试）。

> ⚠️ **`features=true / hasDeity=false` 是合法组合** —— 跨虫线出的灵兽就是这样。
> 不要当成数据异常。

> ❌ **红线**：蠃虫（`SpeciesFamily.LUO`）与「不入十类」的 `deityId` 恒为 `null`。
> 「圣人」依典籍**不设形**（ADR-020）。**禁止**为蠃虫补拟人化替代神兽。

### 6.2.4 融合（⭐ v2.4 新增）

重复宠物的去处。**详见 [10-融合机制设计](./10-融合机制设计.md)**。

```kotlin
object FusionRules {
    const val costGold = 200
    fun markWeightOf(rarity: Rarity): Int?      // 1/2/4/8/16，灵兽返回 null
    fun thresholdFor(rarity: Rarity): Int?      // 5/8/12/20，神话返回 null
    fun check(target: Pet, material: Pet): FusionCheck
    fun resolve(target: Pet, targetMarks: Int, material: Pet): FusionResult
}
```

> ❌ **红线**：融合**永远不能产出灵兽**（ADR-017）。三重防守 + 1476 组穷举测试守住。
> ❌ **不要给融合加属性加成** —— 会造成"同稀有度不等价"，与 ADR-021 同源（理由见 10 §六）。

### 6.3 数值中枢

**所有策划参数都在 `GrowthRules`**，包括：

- 等级上限、升级公式
- 孵化时长（`HATCH_DURATION_BY_RARITY`，按稀有度分钟级）、加速道具效果
- 互动类型的经验/亲密度/冷却/每日上限（`InteractionType`，含 `DESKTOP` 桌面互动）
  > ⚠️ **v2.3 调参**：6 项互动的 `exp` 全部 ×3，`DAILY_EXP_CAP 5000 → 6000`。
  > 不变量：`DAILY_EXP_CAP >= dailyExpFromInteractions`（否则是够不着的空配置）。
  > **`intimacy` 未调整** —— 它是"陪伴深度"的度量。
- **`PairingRules`**：配对条件（成年/亲密≥70/**3 天冷却**/最多 **5** 后代（NPC 搭档 **3**）/邀请 3 天有效）
- **`BreedingRules`**：遗传（`RARITY_DISTRIBUTION`、`pairingKindOf`、`offspringRarity`、`offspringSpecies`、`isPairingSuccessful`、`resolveOffspringRarity`）
- **`ExoticBloodRules`**：灵血传承（`MAX_BLOOD`、`awakenRateOf`、`carrierBloodOf`、`inheritedBlood`、`shouldAwaken`）
- **`MutantPityRules`** ⭐ v2.3：灵兽冷启动保底（`PITY_THRESHOLD=20`、`PITY_STEP=0.02`、`MAX_PITY_RATE=0.40`、`pityBonusOf`、`shouldTrigger`、`nextStreak`）

> 📌 **改数值只改这一个文件**，不要散落到业务代码。
> 📌 **遗传函数必须是纯函数**（随机数通过参数传入），否则无法写单测。
> 📌 **任何影响节奏的改动必须重跑 `tools/acquisition_sim.py` 并同步 `docs/08`**（ADR-024）。

### 6.3.1 配对（替代结婚 ⭐ v2.0/v2.1）

**`Marriage` / `MarriageRules` / `MarriageStatus` 已全部改名为 `Pairing` / `PairingRules` / `PairingStatus`。**

| 概念 | 说明 |
|------|------|
| `Pairing` | 配对关系，含 `partnerIsNpc` / `isSameOwner` / `pairedAt` |
| `PairingStatus` | `PENDING`（真人待确认）/ `PAIRED`（生效）/ `RELEASED`（解绑）/ `EXPIRED`（邀请过期） |
| `PairingKind` | `SAME_FAMILY` / `CROSS_FAMILY` / `EXOTIC_MIX` / `EXOTIC_PAIR` |
| 归属 | **宠物归属永不变更**（配对不是婚姻，没有"嫁过去"） |
| 真人配对 | `PENDING` → 对方确认 → `PAIRED` |
| NPC 配对 | 直接 `PAIRED`，**免确认** |

> ❌ **禁止重新引入"结婚"机制**（见 ADR-008、PRD §11.1）。`PetStage.canMarry` 已改名 `canPair`。

## 十、常见坑与注意事项

| 坑 | 说明 |
|----|------|
| **Room 枚举** | Room 不支持枚举，Entity 存 `Int`/`String`，用 `fromId()` 还原 |
| **Migration** | 每次改表必须写 Migration，禁止长期用 `fallbackToDestructiveMigration` |
| ⭐ **领域字段忘了映射** | **新增领域字段必须同时补齐三处：`PetEntity` 列 + `PetMapper` 双向映射 + Migration**。领域层单测**不经过数据库**，漏映射时它们依然全绿 —— ADR-023「灵血传承」就因此静默失效过（`PetMapperTest` 的往返测试现已守住） |
| **Flow 收集** | Fragment 中用 `collectInView`（已绑定 `viewLifecycleOwner`），禁止裸 `collect` |
| **ViewBinding 泄漏** | `BaseFragment` 已在 `onDestroyView` 置空，子类勿再持有 binding |
| **悬浮窗权限** | 各厂商 ROM 差异大，需逐个适配 |
| **Rive 资源缺失** | `PetAssetResolver` 已有降级逻辑，美术未交付也不会崩 |
| **动画打断** | `render()` 已做幂等保护，相同状态不重复触发 |
| **文件编码** | 全部 UTF-8，Kotlin 文件带 BOM 会导致编译警告 |
| ⭐ **枚举"幽灵别名"** | **不要在枚举里加历史别名常量**。枚举常量是独立条目不是别名，会污染 `entries`。兼容一律走 `fromName()` |
| ⭐ **`Rarity.entries` 误用** | 抽取相关逻辑**必须用 `Rarity.drawableEntries()`**，否则「灵兽」会混进抽取池 |
| ⭐ **用"指定稀有度"绕开 ADR-017** | **不允许**。任何保底 / 指定档位的入口都必须经 `Rarity.maxDrawable` 钳制上限；`BlindBoxEngine.draw` 已内置，新写同类逻辑时照做（`BlindBoxEngineTest` 有断言守住） |
| ⭐ **让灵血参与属性计算** | **不要做**。灵血只影响觉醒概率，不参与数值（ADR-021）。`ExoticBloodRulesTest` 有 `blood never affects attributes` 断言守住 |
| ⭐ **遗传函数写成非纯函数** | 随机源必须作为参数传入，否则单测无法固定种子、行为不可复现 |
| ⭐ **跨虫/同虫系数反转** | 必须保持 `同虫 1.0 < 跨虫 1.35 < 异兽混配 1.8 < 异兽对 2.0`，反转会摧毁跨虫社交激励 |
| ⭐ **给蠃虫补神兽形象** | **不要做**（ADR-020）。倮虫之长即"人"，做成可穿戴外观皮属结构性文化风险。图鉴留白即可，且**不得**用"螺贝之灵"之类替代品（那会把"依据典籍不设"降级为"自我审查"） |
| ⭐ **让五虫影响数值** | **不要做**（ADR-021）。`PetAttributes.ofLevel` 只接受 `Rarity` + 物种级 `tendency`。一旦类群参与数值，玩家被迫在"战力"与"喜欢"间取舍，并使弱虫属玩家受结构性挫败 |
| ⭐ **混用两个神兽通道** | `hasDeityFeatures`（稀有度 ≥ 传说，抽卡回报）与 `hasDeity`（`Pet.hasFullDeityForm`，出生结算）**是两层**。跨虫灵兽 = `features=true / hasDeity=false`，**这是合法组合，不是数据异常**（ADR-026） |
| ⭐ **在渲染时现算神兽形态** | **不要做**。判定需要"诞生时的配对类型"，而 `parentIdA/B` 只指向父母、反推不出来。必须用落库的 `Pet.hasFullDeityForm` |
| ⭐ **给融合加属性加成** | **不要做**。会造成"同稀有度不等价"，与 ADR-021 同源。融合的即时反馈是**经验 + 印记进度**（见 [10 §六](./10-融合机制设计.md)） |
| ⭐ **让融合产出灵兽** | **绝对不要**（ADR-017）。三重防守：灵兽不可作材料 / 不可作目标 / `resolve()` 兜底。`FusionRulesTest` 有 **1476 组穷举**守住 |
| ⭐ **凭直觉设保底阈值** | 阈值必须对着**实测连击分布**去设。初版"30 次"在实测中因连击数中位只有 7~13 次而**几乎不触发** → 校准为 20 次。同类教训还见于 `DAILY_EXP_CAP`（旧值低于实际可得，是个空配置） |
