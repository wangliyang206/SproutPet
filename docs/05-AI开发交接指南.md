## 一、30 秒了解项目

**萌芽宠物 SproutPet** 是一款 Android 养成类 App。

- **核心玩法**：领盲盒蛋 → 孵化 → 破壳出幼崽 → 互动养成 → **配对生育**（真人/NPC）→ 族谱；宠物还会**上桌面**陪伴，并在家庭情景中互相反应
- **物种体系**：**五虫**（蠃鳞毛羽昆）+「不入十类之种」，共 **18 种 / 6 类群**
- **稀有度**：**6 档**（普通/稀有/史诗/传说/神话 + **异兽**，异兽不可抽取、仅遗传产生）
- **技术栈**：Kotlin + XML + MVVM + Hilt + Room + Retrofit + **Rive（宠物渲染）**
- **工程位置**：`E:\git\SproutPet`
- **包名**：`com.sproutpet.pet`
- **架构**：`app`（UI）+ `core`（领域/数据/基础设施）双模块

## 五、代码红线（**违反将导致返工**）

### 5.1 架构红线

| 编号 | 规则 | 反例 |
|------|------|------|
| A1 | UI 层禁止写业务逻辑 | ❌ 在 Fragment 里写 `if (exp >= expToNext) level++` |
| A2 | ViewModel 禁止持有 View/Activity/Fragment 引用 | ❌ `class VM(val activity: Activity)` |
| A3 | ViewModel 禁止直接访问 DAO / 发网络请求 | ❌ `petDao.queryById()` 写在 VM 里 |
| A4 | UseCase 禁止依赖 Android 类 | ❌ `import android.content.Context` 在 UseCase 中 |
| A5 | Repository 禁止写业务规则 | ❌ 在 Repo 里判断"能否结婚" |
| A6 | 依赖方向只能是 app → core | ❌ core 里 import app 的类 |

### 5.2 代码质量红线

| 编号 | 规则 |
|------|------|
| C1 | 禁止魔法数字 —— 所有数值写入 `GrowthRules` 或 `const val` |
| C2 | 禁止 `!!` —— 用 `?:` 或 `requireNotNull(x) { "原因" }` |
| C3 | 禁止 `GlobalScope` —— 用 `viewModelScope` / `lifecycleScope` |
| C4 | 所有公开函数必须有 KDoc |
| C5 | 所有 UseCase 必须有单元测试 |
| C6 | 每个 Model/Entity/DTO 字段必须有中文注释说明含义 |

### 5.3 合规红线（**最高优先级，不可协商**）

| 编号 | 规则 | 原因 |
|------|------|------|

## 六、必读：核心领域概念

### 6.1 宠物生命周期

```kotlin
enum class PetStage(val id: Int, val displayName: String) {
    EGG(0, "蛋"),
    HATCHING(1, "破壳"),
    BABY(2, "幼崽"),
    JUVENILE(3, "少年"),
    ADULT(4, "成年"),
    ELDER(5, "长者"),
    RETIRED(6, "隐居"),   // ⭐ v2.1 新增
}
```

| 阶段 | id | 能力 | 在桌面 |
|------|----|------|-------|
| EGG | 0 | 孵化中 | ❌ |
| HATCHING | 1 | 破壳动画 | ❌ |
| BABY | 2 | 基础互动 | ❌ |
| JUVENILE | 3 | 玩耍/训练/换装 | ✅ |
| ADULT | 4 | **配对**、排行、族谱 | ✅ |
| ELDER | 5 | 传承、建家族 | ✅ |
| **RETIRED** | 6 | **隐居**（v2.0 起取代"死亡"，族谱保留，不再交互） | ❌ |

> 关键方法：`canPair`（原 `canMarry`，**已改名**）、`isOnDesktop`。

### 6.2 稀有度（6 档 ⭐）

```kotlin
enum class Rarity(val id: Int, val displayName: String, ...) {
    COMMON(0, "普通"), RARE(1, "稀有"), EPIC(2, "史诗"),
    LEGENDARY(3, "传说"), MYTHIC(4, "神话"),
    MUTANT(5, "异兽"),   // ⭐ v2.1 新增，weight=0，不可抽取
}
```

影响：开出概率、成长系数、孵化时长、外观特效、遗传概率。

**⭐ v2.1 最重要的两条规则**

1. **`MUTANT`（异兽）永不进抽取池**。所有抽取路径必须用 `Rarity.drawableEntries()`（会过滤 `isDrawable=false`），**不要用 `Rarity.entries`**。异兽只能由 `BreedingRules.offspringRarity/offspringSpecies` 遗传产生。
2. **遗传是"概率漂移，不降级"**：以 `max(父母稀有度)` 为基准做加权漂移，**永不跌破基准**。这保证用户投入不被背叛，同时保留上漂惊喜。

### 6.2.1 物种体系：五虫（⭐ v2.1 核心）

```kotlin
enum class SpeciesFamily(val deity: String, val definition: String) {
    LUO("圣人", "蠃虫 · 无鳞无甲无羽无毛者"),
    LIN("蛟龙", "鳞虫 · 有鳞者"),
    MAO("麒麟", "毛虫 · 有毛者"),
    YU("凤凰", "羽虫 · 有羽者"),
    KUN("神龟", "昆虫 · 有甲者"),
    UNCATEGORIZED("—", "不入十类之种"),   // 异兽类，不可抽取
}
```

**分类依据**：《西游记》第五十八回如来原话 ——「周天之内有五虫，乃蠃、鳞、毛、羽、昆」。

> 中国神话体系中的神兽/灵兽/异兽**本就内含于五虫**：五虫之"长"即神兽（凤凰/麒麟/蛟龙/神龟/圣人），而"不入十类之种"（如混世四猴）即异兽。

**规模**：**18 种物种 / 6 类群**，每类群 3 种。详见 [07-五虫体系设计](./07-五虫体系设计.md)。

```kotlin
object PetSpecies {
    val FIVE_WORMS: List<SpeciesFamily>   // 蠃鳞毛羽昆，顺序即如来原话顺序
    // 每族 3 种：蠃虫 SNAIL/BUBBLE_FROG/SOFT_OCTOPUS，鳞虫 KOI/GRASS_SNAKE/LITTLE_DRAGON ...
}
```

**⚠️ 三条不可违反的红线**

1. **`SpeciesFamily` 枚举本体只有 6 个值**。历史别名（`BIRD`/`MAMMAL`/`OVINE`/`FELINE`/`EXOTIC`）**只能存在于 `fromName()` 字符串映射里**，绝不可写成枚举常量。枚举常量是独立条目不是别名，混入会污染 `entries` → 任何遍历类群的 UI 出现幽灵项。已有测试守住。
2. **类群不落库**，由 `species.family` 派生，避免双重真相源。
3. **跨虫上漂系数必须 > 同虫**（`1.0 < 1.35 < 1.8 < 2.0`）。这是**刻意设计**，用数值奖励跨虫社交；反转会直接摧毁社交生态。已有测试守住。

**⭐ 两条已决策的边界（不要越界）**

| 决策 | 结论 | 在代码里怎么体现 |
|------|------|-----------------|
| **ADR-020** | 蠃虫之长「圣人」**不做形象** | `SpeciesFamily.LUO.hasDeityForm == false`（其余四虫为 `true`）。**禁止**在 `deity/` 下加蠃虫层，也禁止加替代品 |
| **ADR-021** | 五虫**不影响属性数值** | `PetAttributes.ofLevel(level, rarity, tendency)` —— **不接收** `SpeciesFamily`。各物种 `tendency` 已跨类群打散，避免类群间接入数值 |

**❓ 那五虫靠什么让玩家在乎？**（这是新人最常问的）

| 手段 | 说明 |
|------|------|
| 配对加成 | 跨虫上漂 1.35 > 同虫 1.0 —— 用**遗传概率**而非属性奖励跨虫 |
| 图鉴收集 | 按蠃鳞毛羽昆分页，集齐一类有称号（纯荣誉） |
| 身份标识 | 族谱图例按五虫分色，宠物卡面显示虫属 |
| 神兽形态 | 四虫各有其长，是外观的终极目标 |
| 叙事文案 | 直接从典籍取词，文学性本身就是价值 |

> 📖 完整论证见 [07-五虫体系设计](./07-五虫体系设计.md) §9之一。

### 6.3 数值中枢

**所有策划参数都在 `GrowthRules`**，包括：

- 等级上限、升级公式
- 孵化时长（`HATCH_DURATION_BY_RARITY`，按稀有度分钟级）、加速道具效果
- 互动类型的经验/亲密度/冷却/每日上限（`InteractionType`，含 `DESKTOP` 桌面互动）
- **`PairingRules`**：配对条件（成年/亲密≥70/异主/7天冷却/最多5后代/邀请3天有效）
- **`BreedingRules`**：遗传（`RARITY_DISTRIBUTION`、`pairingKindOf`、`offspringRarity`、`offspringSpecies`、`isPairingSuccessful`）

> 📌 **改数值只改这一个文件**，不要散落到业务代码。
> 📌 **遗传函数必须是纯函数**（随机数通过参数传入），否则无法写单测。

### 6.3.1 配对（替代结婚 ⭐ v2.0/v2.1）

**`Marriage` / `MarriageRules` / `MarriageStatus` 已全部改名为 `Pairing` / `PairingRules` / `PairingStatus`。**

| 概念 | 说明 |
|------|------|
| `Pairing` | 配对关系，含 `partnerIsNpc` / `isSameOwner` / `pairedAt` |
| `PairingStatus` | `PENDING`（真人待确认）/ `PAIRED`（生效）/ `RELEASED`（解绑）/ `EXPIRED`（邀请过期） |
| `PairingKind` | `SAME_FAMILY` / `CROSS_FAMILY` / `EXOTIC_MIX` / `EXOTIC_PAIR` |
| 归属 | **宠物归属永不变更**（配对不是婚姻，没有"嫁过去"） |
| 真人配对 | `PENDING` → 对方确认 → `PAIRED` |
| NPC 配对 | 直接 `PAIRED`，**免确认** |

> ❌ **禁止重新引入"结婚"机制**（见 ADR-008、PRD §11.1）。`PetStage.canMarry` 已改名 `canPair`。

### 6.4 渲染抽象（重要）

业务层只产出 `PetRenderState`，渲染层负责翻译成动画：

```
业务逻辑 → PetRenderState → PetRenderer.render() → 具体动画
```

**当前实现状态**

| 实现 | 状态 |
|------|------|
| `FramePetRenderer` | Phase 1 实现（帧动画+属性动画） |
| `RivePetRenderer` | Phase 3 实现 |
| `LottiePetRenderer` | Phase 3 实现（降级） |

## 十、常见坑与注意事项

| 坑 | 说明 |
|----|------|
| **Room 枚举** | Room 不支持枚举，Entity 存 `Int`/`String`，用 `fromId()` 还原 |
| **Migration** | 每次改表必须写 Migration，禁止长期用 `fallbackToDestructiveMigration` |
| **Flow 收集** | Fragment 中用 `collectInView`（已绑定 `viewLifecycleOwner`），禁止裸 `collect` |
| **ViewBinding 泄漏** | `BaseFragment` 已在 `onDestroyView` 置空，子类勿再持有 binding |
| **悬浮窗权限** | 各厂商 ROM 差异大，需逐个适配 |
| **Rive 资源缺失** | `PetAssetResolver` 已有降级逻辑，美术未交付也不会崩 |
| **动画打断** | `render()` 已做幂等保护，相同状态不重复触发 |
| **文件编码** | 全部 UTF-8，Kotlin 文件带 BOM 会导致编译警告 |
| ⭐ **枚举"幽灵别名"** | **不要在枚举里加历史别名常量**。枚举常量是独立条目不是别名，会污染 `entries`。兼容一律走 `fromName()` |
| ⭐ **`Rarity.entries` 误用** | 抽取相关逻辑**必须用 `Rarity.drawableEntries()`**，否则「异兽」会混进抽取池 |
| ⭐ **遗传函数写成非纯函数** | 随机源必须作为参数传入，否则单测无法固定种子、行为不可复现 |
| ⭐ **跨虫/同虫系数反转** | 必须保持 `同虫 1.0 < 跨虫 1.35 < 异兽混配 1.8 < 异兽对 2.0`，反转会摧毁跨虫社交激励 |
| ⭐ **给蠃虫补神兽形象** | **不要做**（ADR-020）。倮虫之长即"人"，做成可穿戴外观皮属结构性文化风险。图鉴留白即可，且**不得**用"螺贝之灵"之类替代品（那会把"依据典籍不设"降级为"自我审查"） |
| ⭐ **让五虫影响数值** | **不要做**（ADR-021）。`PetAttributes.ofLevel` 只接受 `Rarity` + 物种级 `tendency`。一旦类群参与数值，玩家被迫在"战力"与"喜欢"间取舍，并使弱虫属玩家受结构性挫败 |
