## 一、为什么要有这份文档

修复前（`docs/09` G-02）的实际情况是：

> **消耗侧写得清清楚楚，产出侧一片空白。**

| 侧 | 修复前的状态 |
|----|------------|
| **消耗** | 配对 3,000 金币（[00 §2.5](./00-产品需求文档PRD.md)）· 融合 200 金币（[10](./10-融合机制设计.md)）· 商店道具 50~3,000 金币（`ItemRegistry`）—— **全部定稿** |
| **产出** | 只有 [00 §6.1](./00-产品需求文档PRD.md) 一句话：「任务、离线收益、售卖」—— **没有任何一个数字** |

后果非常具体：**核心长线玩法（配对生育）的前置条件是"有 3,000 金币"，
而玩家怎么赚到 3,000 金币，文档里是空白。** 做配对 UI 的那天必然卡住。

本文档补齐产出侧，并给出**唯一的平衡锚点**，让"配对要攒几天"这个问题有确定答案。

## 二、货币定义

| 货币 | 定位 | 产出 | 用途 |
|------|------|------|------|
| **金币** | 软货币 | 签到 · 日常任务 · 离线收益 · 道具回收 · 成就 | 食物/道具/加速 **· 配对 3,000 · 融合 200** |
| **钻石** | 硬货币 | 充值 · 签到满轮 · 成就 · 活动 | 高级道具 · 瞬时孵化 · 保底道具 · 限定皮肤 |

> **非付费可达**：所有道具都能靠任务/活动拿到（[00 §6.3](./00-产品需求文档PRD.md) 的承诺）。
> 钻石因此设有**免费日上限**（见 §六），防止某次活动放量冲垮硬货币体系。

## 三、金币产出（权威口径）

### 3.1 每日签到

| 项目 | 数值 |
|------|------|
| 基础金币 | **100** |
| 连续第 3 天额外 | +20 金币 |
| 连续第 7 天额外 | +100 金币 + **1 钻石** |
| 轮次 | 7 天一轮，循环 |

零门槛，负责"每天回来就有确定性收益"。

### 3.2 日常任务清单（8 项）

| 任务 | 条件 | 金币 | 经验 |
|------|------|-----:|-----:|
| 每日签到 | 登录游戏 | 100 | 0 |
| 互动达人 | 完成 10 次互动 | 80 | 100 |
| 大厨时间 | 喂食 5 次 | 60 | 90 |
| 玩伴时光 | 玩耍 3 次 | 100 | 120 |
| 健身教练 | 训练 2 次 | 120 | 150 |
| 干干净净 | 清洁 3 次 | 60 | 60 |
| 桌面陪伴 | 桌面互动 20 次 | 90 | 90 |
| 串门拜访 | 访问好友 1 次（NPC 亦可） | 100 | 125 |
| **合计** | | **710** | **735** |

两点设计说明：

- **任务覆盖全部 6 种互动类型**，不新增"为了做任务而做的动作"——
  日常任务是**对既有陪伴行为的确认**，不是额外的作业。
- **串门是唯一的社交向任务**。有它，日常任务才不只是"多喂两次饭"，
  而是在每天推一次社交曝光；而配对本就是核心长线玩法，需要玩家先认识人。

### 3.3 离线收益

| 项目 | 数值 |
|------|------|
| 金币 | **25 / 小时** |
| 上限 | **12 小时**（超出不计） |
| 计算 | `floor(min(离线时长, 12h) / 1h) × 25`，**向下取整到整小时** |
| 满额日收益 | **300** |

**⚠️ 离线只给金币，不给经验**（这是刻意的约束，不是遗漏）：

若离线也给经验，会出现一个荒谬的反向激励 ——
**关掉 App 比开着 App 升级更快**（在线要手动点，离线躺着就有）。
本产品是「治愈陪伴」，核心价值是**在线互动的过程**，所以离线的定位是
"宠物自己在家照顾自己"的**照看津贴**：只给软货币，不给成长。
让金币成为"回来花"的理由，而不是"别回来"的理由。

向下取整到整小时，是为了避免玩家为了"卡最后 59 分钟"而精确掐表上线，
把陪伴变成打卡任务。

### 3.4 道具回收

回收价 = **商店价 × 50%（向下取整）**，`shopPriceGold` 为空的道具不可回收。

定在 50%：定 100% 会让"买入 → 卖出"变成无损套利，商店退化成提款机；
定太低又会让误买的玩家感觉被惩罚。

### 3.5 抽蛋门票的产出（🆕 v1.2）

抽蛋的定位是**素材供给**（生育才是上限路径），所以门票刻意**挂在陪伴行为上**，
而不是做成独立于宠物的日常：

| 来源 | 额度 | 说明 |
|------|------|------|
| 每日签到 | **1 抽** | 零门槛（与 §3.1 的签到金币同一动作，不额外要求操作） |
| 日常任务全清（8/8） | **1 抽** | 挂在**全清**而非"完成任意一个" —— 抽蛋必须是照顾宠物的副产品 |
| 金币购买 | 300 / 个 · **日限 1** | 补票口 |
| 钻石购买 | 60 / 个 | 付费通道 |
| **首只孵化成功**（一次性） | **+10 抽** | 第一个养成成果的奖励，刚好一次十连；**只发一次**（DataStore 事务内判重），不进日常收入 |

> 数值中枢 = `core/domain/gacha/GachaRules.kt`。**30 天 60 抽 ≈ 6.25 只史诗+**，
> 与「家在册 6 只」的节奏咬合（GachaRules 的锚点由 `GachaRulesTest` 守住）。

### 3.6 成就 / 活动

- **成就**：一次性金币+钻石奖励。**具体清单待成就系统落地时定稿**（Phase 8），
  但单个成就的钻石数**不得超过 50**（`EconomyRules.GemRules.MAX_ACHIEVEMENT_GEM`）。
- **活动**：运营配置，不写死。硬约束是**免费钻石日上限 10**（见 §六）。

## 四、金币消耗

| 用途 | 金额 | 出处 |
|------|-----:|------|
| **配对生育** | **3,000** | `GrowthRules.PairingRules.costGold` |
| **融合** | **200** | `FusionRules.costGold` |
| 食物（谷物饲料 / 营养便当） | 50 / 200 | `ItemRegistry` |
| 训练道具（铁哑铃 / 知识之书） | 150 | `ItemRegistry` |
| 成长果实 | 500 | `ItemRegistry` |
| 加速道具（沙漏碎片 / 时光沙漏） | 200 / 3,000 | `ItemRegistry` |
| 社交（一束花） | 100 | `ItemRegistry` |
| **盲盒（抽蛋）** | **300 / 个 · 日限 1** | `GachaRules.GOLD_PRICE_PER_BOX` / `MAX_GOLD_PURCHASE_PER_DAY`（v1.2 定稿）。**日限是刻意的** —— 钱买不来无限抽 |

> 加速类存在**明显的两条定位**：`speed_up_hour`（200 金币）是日常小额，
> `speed_up_day`（3,000 金币）等同于一次配对费 —— 后者实际上是**钻石定位**，
> 金币标价只作为"极长期玩家的兜底"。若后续发现它卖不动，属预期内。

## 五、⭐ 平衡锚点（本文件的核心）

整个经济系统只有**一条**必须满足的关系：

```
每日金币收入 ≥ 配对花费 ÷ 生育冷却
```

也就是**一个冷却周期内必须攒得起一次配对费**。否则玩家会遇到
「成年了、亲密够了、异主也对 —— 但就是没钱」，卡死在核心玩法门口。

| 量 | 值 | 推导 |
|----|----|------|
| 签到 + 全任务 | 710 | §3.2 |
| 满额离线 | 300 | §3.3 |
| **每日金币上限** | **1,010** | `EconomyRules.maxGoldPerDay` |
| 配对费 | 3,000 | `PairingRules.costGold` |
| **攒够配对费** | **2.97 天** | `EconomyRules.daysToAffordPairing` |
| 生育冷却 | **3 天** | `PairingRules.cooldownMs` |
| **融合费** | **0.2 天** | 当天就能做 |
| 抽蛋补票（金币价 300） | **0.30 天** | 当天收入就够 1 抽；**日限 1** 锁住"有钱就能无限抽" |

结论：**2.97 天 ≈ 3 天冷却**，两边同时到位。
重复宠物的去处（融合）当天可用，不会让背包堆积。

> 这条锚点由 `EconomyRulesTest` 守住：任何一侧被单独改动，测试立刻变红。

## 六、钻石

| 途径 | 额度 |
|------|------|
| 签到满轮（7 天） | 1 |
| 成就 | 单次 ≤ 50 |
| 活动 | 运营配置 |
| 充值 | — |
| **免费合计日上限** | **10** |

> 钻石的一条具体出口：**盲盒 60 / 个**（`GachaRules.GEM_PRICE_PER_BOX`）——
> 愿意付费的人不必等每日 2 抽的免费额度。

免费钻石之所以要设日上限：硬货币一旦放量，限定皮肤与保底道具的价值会瞬间蒸发，
而**已经付费的玩家会感到被背叛** —— 这是最难修复的一类口碑伤害。

## 七、产品决策：宠物**不可售卖**

[00 §6.1](./00-产品需求文档PRD.md) 的"售卖"字样曾留下歧义。**本文件正式收口：
"售卖"仅指道具回收，宠物永远不能卖。**

两条理由，任一条都足够：

1. **与「治愈陪伴」定位冲突** —— 把陪伴对象标价卖掉，会摧毁整个情感叙事；
   用户会立刻把"宠物"重新归类为"资源"，而资源是可以被优化的。
2. **族谱需要保留血缘记录** —— 卖宠会让后代失去父母节点，
   直接破坏 [00 §2.7](./00-产品需求文档PRD.md) 的族谱与传承系统。

**重复宠物的正确去处是融合**（[10-融合机制设计](./10-融合机制设计.md)）：
那是"投入换成长"，不是"变现"。
且融合的副宠是**「入后山」而非消失**（保留在图鉴与族谱），情感上不构成损失。

## 八、经验与金币的关系（别混）

| 来源 | 给金币 | 给经验 | 是否占每日经验上限 |
|------|:-----:|:-----:|:-----------------:|
| 互动（6 种） | ✗ | ✓ | **是** |
| 日常任务 | ✓ | ✓ | **是** |
| 离线收益 | ✓ | ✗ | 不适用（无经验） |
| 道具回收 | ✓ | ✗ | 不适用 |
| 融合 | ✗（反而消耗） | ✓（给目标宠） | 否（独立通道） |

**关键等式**（由 `EconomyRulesTest` 守住）：

```
互动 5,265 + 日常任务 735 = 6,000 = GrowthRules.DAILY_EXP_CAP
```

即"打满一切可刷来源"**正好触顶**。修复前日上限 5,000 面对互动打满仅 1,755 的
现实是个"够不着的空配置"，任何人看它都会误判真实节奏。现在上限真的会拦到人 ——
它终于开始履行"防脚本刷经验"的职责。
