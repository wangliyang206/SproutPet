## 一、为什么要有它

**盲盒必然会给出重复宠物**，而生育又会加速这个过程 —— 一只宠一生 5 个后代，
三代之后玩家的仓库里就堆满了同物种的重复个体。没有去处时会发生三件事：

1. **仓库变成垃圾场** —— 列表越滚越长，玩家不再逐只查看，情感连接断裂
2. **抽卡价值被稀释** —— 抽到重复不再是"可惜"，而是"又来了"，挫败感直接落到付费点
3. **宠物变成耗材** —— 一旦玩家在心里把宠物归为"重复品"，整个"陪伴"的立意就站不住了

所以需要一个机制，**把重复消化掉、而且不破坏情感基调**。

---

## 二、它是什么（一句话）

> **挑一只留下的，把重复的那只"喂"给它，留的那只变强，喂的那只入后山。**

```
        融合前                      融合后
   ┌──────────┐               ┌──────────┐
   │ 目标宠    │  ← 获得        │ 目标宠    │  稀有度 +1 档（印记满时）
   │ 稀有度 史诗│    印记/经验    │ 稀有度 传说│  经验 + 副宠等级×50
   └──────────┘               └──────────┘
   ┌──────────┐
   │ 副宠      │  → 入后山      （保留在族谱与图鉴记录中，不可取回）
   │ 稀有度 稀有│
   └──────────┘
```

## 三、与「生育」的分工（**别混，这是两套机制**）

| | **融合**（本文档） | **生育**（[06 §2.5](./06-物种与稀有度设计.md)） |
|---|---|---|
| 一句话 | 两只同类 → 一只变强 | 两只宠 → 生一个**新**个体 |
| 方向 | **纵向加深**（个体变强） | **横向铺开**（家族变大） |
| 消耗 | 1 只副宠 + 200 金币 | 3000 金币 + 3 天冷却 |
| 产出 | 目标宠稀有度上漂 | 1 个新后代 |
| 能否产出灵兽 | ❌ **永不能**（ADR-017 红线） | ✅ 唯一途径 |
| 解决什么 | 重复宠没去处 | 家族延续 / 长线目标 |

> 📌 **二者唯一的交集是"都消耗宠物"**，产出物完全不同。设计上互不依赖，可以分别调参。

## 四、三条硬规则

### 4.1 必须同物种

羽虫只能喂羽虫。理由：

- 跨物种融合会让**物种轴失去意义**（物种的唯一作用就是决定外观与配对规则）
- 会诱导玩家为融合去凑毫不相干的宠物，破坏"收集"的心智

> 校验由 `FusionRules.check` 的 `SPECIES_MISMATCH` 守住。

### 4.2 副宠「入后山」，不消失

副宠退出桌面与配对，但**保留在族谱与图鉴记录里**。

- ✅ **这是情感产品的底线** —— 不能真的"吃掉"一只玩家养过的宠物
- ❌ 但**不可取回** —— 不可逆是这份取舍的分量所在

> 因此 UI 必须**二次确认**，并在确认文案里明确写"入后山"而不是"消失"。
> 文案建议：「它会去后山住下，不再出现在桌面。族谱里仍留着它的名字。」

### 4.3 灵兽永远不能由融合产生（ADR-017 红线）

三重防守，任何一层都够：

1. `markWeightOf(MUTANT)` 返回 `null` → **灵兽不能作为材料**
2. `thresholdFor(MUTANT)` 返回 `null` → **灵兽不能作为目标**
3. `resolve()` 内部还有一道 `next == Rarity.MUTANT` 的兜底 → 即便前两道被改坏，也不会越界

> 🧪 由 `FusionRulesTest.no input combination ever produces a mutant` 穷举
> （6 档 × 41 组印记 × 6 档材料 = 1476 种组合）守住。

## 五、印记与上漂

### 5.1 印记权重（按副宠稀有度）

| 副宠稀有度 | 印记 |
|---|---|
| 普通 | **1** |
| 稀有 | **2** |
| 史诗 | **4** |
| 传说 | **8** |
| 神话 | **16** |
| 灵兽 | ❌ 不可作为材料 |

按 2 的幂递增，是为了制造**取舍张力**：越稀有的副宠越舍不得喂，但喂了回报越大。

### 5.2 上漂阈值（按目标宠当前稀有度）

| 目标当前 | 需要印记 | 通俗说法 |
|---|---|---|
| 普通 | **5** | 5 只普通 或 1 只史诗 + 1 只普通 |
| 稀有 | **8** | 4 只稀有 / 2 只史诗 |
| 史诗 | **12** | 3 只史诗 / 1 只传说 + 1 只史诗 |
| 传说 | **20** | 1 只神话 + 1 只史诗 |
| 神话 | — | **终点，不可再融合** |

### 5.3 两条设计意图

- **只升不降** —— 融合永远让目标变好，不存在"投入了却变差"
- **溢出保留** —— 上漂后剩余印记**带到下一档**，前期投入不会被清零

> 例：普通目标（阈值 5）+ 神话副宠（权重 16）→ 16 − 5 = 11，11 ≥ 8 再升一档 → **普通直升史诗**，余 3 印记。

### 5.4 为什么神话是终点

神话之上就是灵兽，而融合**不能产出灵兽**。若允许对神话融合，玩家会白白损失副宠却没有任何收益。
因此在 `check` 阶段就**直接拒绝**（`TARGET_AT_CAP`），而不是"允许但无效果"。

## 六、为什么**不**给属性面板加成（重要取舍）

早期设计曾考虑"融合提升属性（递减收益）"。**最终放弃**，理由：

> 那会造成**同稀有度、同物种的两只宠战力不等价** ——
> 玩家会得出"我这只不如别人的"结论。这与 [ADR-021](./04-开发计划.md) 的红线同源：
> **血统与外观不该制造数值优劣。**

替代方案（已实现）：即时反馈改为

1. **给目标宠经验** —— 副宠等级 × 50（满级副宠 = 3000 经验，约等于半级）
2. **可见的印记进度条** —— "还需 3 枚印记上漂"
3. **上漂揭晓动画**

经验是**通用资源**，不会制造"劣等同稀有度"，却能提供确定的即时反馈。

## 七、交互流程（给 UI 的契约）

```
① 选择目标宠（必须是可融合档位：普通 / 稀有 / 史诗 / 传说，已破壳）
        ↓
② 选择副宠（同物种 + 非灵兽 + 已破壳）
        ↓
③ 预览面板
    - 目标：史诗 → 传说（印记 7/12，本次 +8 → 上漂！）
    - 目标获得经验：+1500
    - 副宠：☆☆☆ 将入后山
    - 消耗：200 金币
        ↓
④ 二次确认（副宠不可取回，文案须含"入后山"）
        ↓
⑤ 结算 → 上漂时播揭晓动画；未上漂时进度条 +N
```

### 7.1 必须在 UI 上写清楚的三件事

1. **副宠去哪了** —— "入后山"，不是"消失"，且族谱可查
2. **不可撤回** —— 二次确认
3. **不会产出灵兽** —— 避免玩家期待落空（灵兽只能靠生育，见 06 §2）
