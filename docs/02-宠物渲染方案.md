## 一、要解决的问题

### 1.1 现状（参考同类项目的教训）

传统做法是 `<animation-list>` 帧动画 + 固定尺寸 `ImageView`：

```xml
<!-- 问题所在：只有 2 张图循环，且容器尺寸固定 -->
<animation-list android:oneshot="false">
    <item android:drawable="@mipmap/chicken_blink_0" android:duration="2000" />
    <item android:drawable="@mipmap/chicken_blink_1" android:duration="300" />
</animation-list>

<ImageView android:layout_width="100dp" android:layout_height="100dp" />
```

**三个致命缺陷**

| 缺陷 | 后果 |
|------|------|
| 帧动画 = 切图轮播 | 无骨骼、无形变 → **不立体**，像贴纸 |
| 单一静态容器 | 无法做缩放/位移/旋转的组合运动 → **没有空间感** |
| 无触摸监听 | 点它、拖它、不理它表现一样 → **没有互动** |
| 每套动作 20~25 张 PNG × 5 分辨率 | APK 体积暴涨，新增宠物成本极高 → **只有 2 个模型** |

### 1.2 目标

| 目标 | 验收标准 |
|------|---------|
| 立体感 | 有骨骼形变（挤压/拉伸）、重心偏移、视差跟随 |
| 互动性 | 6 种手势有不同反馈；能感知 App 状态 |
| 资源效率 | 单宠物全套动作 < 1MB；新增宠物边际成本低 |
| 可降级 | 低端机自动降级，不崩溃 |
| 可替换 | 业务层零改动即可换渲染方案 |

## 二、方案选型

| 方案 | 立体感 | 互动 | 体积 | 开发成本 | 美术成本 | 结论 |
|------|-------|------|------|---------|---------|------|
| 帧动画（现状） | ⭐ | ⭐ | 差 | 极低 | 中 | 仅作降级 |
| **Rive** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 优 | 中 | 中 | ✅ **首选** |
| Lottie | ⭐⭐ | ⭐⭐ | 优 | 低 | 低 | 降级备选 |
| Live2D | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 中 | 高 | 高 | Q 版角色用不上 |
| 真 3D | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 差 | 高 | 高 | 仅应用内展柜 |

### 2.1 为什么选 Rive

**1. 立体感来自骨骼 + 网格变形**

Rive 支持把角色部件（头、身、翅、眼、脚）做成**骨骼层级 + 顶点权重网格**，可实现：

- 跳跃时的 **squash（压缩）→ stretch（拉伸）**
- 被拎起时身体纵向拉长、四肢下垂
- 转弯时重心倾斜、尾巴反向摆动

> 注意："立体"≠ 真 3D，而是"有体积感、会形变"。成本远低于真 3D，观感提升巨大。

**2. 互动能力是内建的 State Machine**

| | Lottie | Rive |
|---|--------|------|
| 本质 | 时间轴回放 | 实时状态机 |
| 互动 | 只能 play/pause/loop | 设置输入值，自动平滑过渡 |
| 代码 | 需手动编排多段动画衔接 | 只暴露 inputs，逻辑在美术侧 |

**3. 资源体积小**：`.riv` 矢量 + 压缩，全套动作 200KB~800KB，比几百张 PNG 小 1~2 个数量级。

**4. 跨平台**：同一份 `.riv` 可用于 Android / iOS / Flutter / Web，未来做 iOS 版零重复美术成本。

**5. 换装成本极低**：同一套骨骼换贴图即可，是"个性化装扮"玩法的天然载体。

### 2.2 Rive 的缺点（须提前知晓）

- 编辑器闭源，学习曲线中等（需理解 inputs / state machine 概念）
- 复杂骨骼绑定需专门美术，DIY 易出"关节反向"的劣质效果
- 中文教程较少，以官方文档为主
- **商用授权需确认**（见第六节）

### 2.3 资源组织策略（v2.1 新增 ⭐）

> 背景：物种从 6 种扩到 **18 种**（五虫体系，见 [07-五虫体系设计](./07-五虫体系设计.md)），稀有度从 5 档扩到 **6 档**（新增不可抽取的「异兽」，见 [06-物种与稀有度设计](./06-物种与稀有度设计.md)）。
> 如果按"物种 × 稀有度 × 阶段"暴力出资源，将是 `18 × 6 × 5 = 540` 套，**美术必崩**。必须分层。

**核心原则：把「变化维度」和「不变维度」切开，能复用的绝不多做一份。**

| 维度 | 变化频率 | 实现方式 | 资源量 |
|------|---------|---------|--------|
| **物种** | 低（新增才变） | 独立 `.riv`：各物种专属骨骼比例 + 部件 | 18 套 |
| **成长阶段** | 中（4~5 段） | **同一 `.riv` 内的 State Machine 状态**，用骨骼缩放 + 部件显隐表达"幼→成" | 复用，+0 |
| **稀有度（1~5 档）** | 高（每个体不同） | **不换模型**！用**材质/特效层**：`rarity_tier` Number 输入 → 光效强度、粒子密度、描边颜色 | 复用，+0 |
| **稀有度（第 6 档 · 异兽）** | 低但特殊 | 复用基础骨骼 + **异变层**：异色瞳 / 荧光 / 双色 / 变异体型 | 复用，+0 |
| **基因（花色）** | 最高（每个体唯一） | Rive **`color` 输入 + 部件替换**，换贴图不换骨骼 | 复用，+0 |
| **神兽形态** | 极低（稀有） | 复用基础骨骼 + **部件层/特效层**（额外翅膀/角/尾/光环） | **4 套**附加层（蠃虫不设，见 ADR-020） |

**结论：真正需要美术独立绘制的只有「18 个物种骨骼 + 4 套神兽附加层」，其余全部靠输入通道驱动。**

**Rive 输入通道约定（建议）**

```kotlin
// 渲染层只需把领域数据映射成这几个输入值
object RiveInputs {
    const val STAGE        = "stage"          // Number: 0..5 成长阶段
    const val GROWTH       = "growth"         // Number: 0..1 阶段内进度（用于平滑过渡）
    const val RARITY_TIER  = "rarity_tier"    // Number: 0..5 稀有度档位
    const val IS_MUTANT    = "is_mutant"      // Boolean: 是否异兽（开启异变层）
    const val HAS_DEITY    = "has_deity"      // Boolean: 是否神兽形态（蠃虫恒为 false）
    const val DEITY_ID     = "deity_id"       // Number: 0..3 对应四种可具象的五虫之长
    const val BODY_COLOR   = "body_color"     // Color: 基因主色
    const val ACCENT_COLOR = "accent_color"   // Color: 基因辅色
    const val PATTERN      = "pattern"        // Number: 0..7 花色编号
    const val EMOTION      = "emotion"        // Number: 情绪通道（Phase 5 事件反应）
}
```

> ⚠️ **不要为稀有度出独立模型**。稀有度是"同一只宠物更闪/更贵"，不是"换了一只"。异兽同理——它是**同一只物种发生异变**，不是新物种。这条原则直接决定了美术成本能否收敛。

**资源命名规范**

```
assets/rive/
├── species/
│   ├── luo_snail.riv          # 蠃虫 · 蜗蜗
│   ├── luo_bubble_frog.riv    # 蠃虫 · 泡泡蛙
│   ├── ...
│   └── uncategorized_star_fox.riv   # 不入十类 · 星狐
└── deity/                      # 神兽附加层（叠加在 species 之上）
    ├── deity_fenghuang.riv     # 羽虫之长 · 凤凰（翅膀/尾羽/光环）
    ├── deity_qilin.riv         # 毛虫之长 · 麒麟
    ├── deity_jiaolong.riv      # 鳞虫之长 · 蛟龙
    └── deity_shengui.riv       # 昆虫之长 · 神龟
# ⚠️ 蠃虫之长「圣人」不设形象（ADR-020）：倮虫之长即"人"，
#    做成可穿戴可攀比的外观皮属结构性文化风险。图鉴留白 + 典籍文案代替。
#    ❌ 禁止补"螺贝之灵"之类的替代品 —— 会从"依据典籍不设"降级为"自我审查"。
```

**降级路径（必须实现）**

| 设备档位 | 表现 |
|---------|------|
| 高 | 完整 Rive + 稀有度特效层 + 神兽附加层 + 粒子 |
| 中 | Rive + 稀有度描边，**关闭粒子** |
| 低 | Rive 静态姿势 + 简单位移（无骨骼形变），关闭全部附加层 |
| 极低 | 帧动画占位图（`RenderMode.FRAME`） |

现有 `PetRenderer` 抽象已支持该降级（`RenderMode` 枚举），无需改接口。

### 3.2 抽象层（已完成）

业务层只依赖 `PetRenderer` 接口（`core/domain/pet/PetRenderer.kt`）：

```kotlin
interface PetRenderer {
    fun load(species: PetSpecies, stage: PetStage, genes: PetGenes)
    fun render(state: PetRenderState)
    fun setScale(scale: Float) {}
    fun pause() {}
    fun resume() {}
    fun release()
}
```

**这样设计的好处**：
- Phase 1 用帧动画实现 → Phase 3 换 Rive 实现 → **上层代码零改动**
- 低端机自动降级
- 可通过远程配置灰度切换

### 3.3 Rive 实现（Phase 3 落地）

```kotlin
// app/pet/renderer/rive/RivePetRenderer.kt
class RivePetRenderer(
    private val view: RiveAnimationView
) : PetRenderer {

    private var stateMachine: RiveStateMachine? = null
    private var current: PetRenderState? = null

    override fun load(species: PetSpecies, stage: PetStage, genes: PetGenes) {
        val resId = PetAssetResolver.resolve(species, stage)
        view.setRiveResource(resId, stateMachineName = SM_NAME, autoplay = true)
        stateMachine = view.stateMachines.firstOrNull()

        // 基因 → 渲染参数：让每只宠物长得都不一样
        stateMachine?.apply {
            setNumber("geneBodySize", genes.bodySize)
            setNumber("geneHueShift", genes.hueShift)
            setNumber("genePatternDensity", genes.patternDensity)
            setNumber("geneEyeSize", genes.eyeSize)
            setNumber("geneTailLength", genes.tailLength)
            setNumber("liveliness", genes.liveliness)
        }
    }

    override fun render(state: PetRenderState) {
        if (state == current) return          // 幂等保护，避免打断动画
        current = state
        val sm = stateMachine ?: return
        when (state) {
            is PetRenderState.Idle       -> sm.setBoolean("isIdle", true)
            is PetRenderState.Petted     -> sm.fire("tap")
            is PetRenderState.Excited    -> sm.fire("doubleTap")
            is PetRenderState.Grabbed    -> sm.fire("grab")
            is PetRenderState.Eating     -> sm.fire("eat")
            is PetRenderState.Playing    -> sm.fire("play")
            is PetRenderState.Training   -> sm.fire("train")
            is PetRenderState.Tired      -> sm.setBoolean("isTired", true)
            is PetRenderState.Sleepy     -> sm.setBoolean("isSleepy", true)
            is PetRenderState.Sleeping   -> sm.setBoolean("isSleeping", true)
            is PetRenderState.LevelUp    -> sm.fire("levelUp")
            is PetRenderState.Focusing   -> sm.setBoolean("isFocusing", true)
            is PetRenderState.Marrying   -> sm.fire("marry")
            is PetRenderState.Upset      -> sm.setBoolean("isUpset", true)
            is PetRenderState.Incubating -> sm.setNumber("hatchProgress", state.progress)
            is PetRenderState.Hatching   -> sm.setNumber("hatchProgress", state.progress)
            is PetRenderState.Dragging   -> {
                sm.setNumber("dragX", state.offsetX)
                sm.setNumber("dragY", state.offsetY)
                sm.setBoolean("isDragging", true)
            }
        }
    }

    override fun pause()  { view.pause() }
    override fun resume() { view.play() }
    override fun release() { stateMachine = null; view.stop() }

    private companion object { const val SM_NAME = "MainStateMachine" }
}
```

### 3.4 工厂与降级

// app/pet/renderer/PetRendererFactoryImpl.kt
@Singleton
class PetRendererFactoryImpl @Inject constructor(
    @ApplicationContext private val context: Context
) : PetRendererFactory {

    override fun create(mode: RenderMode): PetRenderer = when {
        !DeviceCapability.canRunRive(context) -> FramePetRenderer()
        mode == RenderMode.RIVE   -> RivePetRenderer(RiveAnimationView(context))
        mode == RenderMode.LOTTIE -> LottiePetRenderer(LottieAnimationView(context))
        else                      -> FramePetRenderer()
    }
}

// 设备能力判断
object DeviceCapability {
    fun canRunRive(context: Context): Boolean {
        val am = context.getSystemService(ActivityManager::class.java)
        val memInfo = ActivityManager.MemoryInfo().also { am.getMemoryInfo(it) }
        val totalMemMb = memInfo.totalMem / 1024 / 1024
        return Build.VERSION.SDK_INT >= Build.VERSION_CODES.N && totalMemMb >= 2048
    }
}

## 四、Rive 状态机规范（**给美术的交付契约**）

### 4.1 State Machine 名称

统一为 **`MainStateMachine`**。

### 4.2 输入定义（必须严格按此命名）

| 输入名 | 类型 | 含义 | 驱动来源 |
|--------|------|------|---------|
| `isIdle` | Boolean | 待机 | 无其他状态时 |
| `isFocusing` | Boolean | 专注陪伴中 | 用户开启专注计时 |
| `isTired` | Boolean | 疲倦（体力<30%） | 属性计算 |
| `isSleepy` | Boolean | 困倦 | 无交互>10min |
| `isSleeping` | Boolean | 睡着 | 无交互>30min |
| `isUpset` | Boolean | 低心情 | 超24h未互动 |
| `isDragging` | Boolean | 拖拽中 | 手势 |
| `dragX` | Number | 拖拽 X 偏移 | 手势 |
| `dragY` | Number | 拖拽 Y 偏移 | 手势 |
| `hatchProgress` | Number 0~1 | 孵化进度 | 孵化计时 |
| `tap` | Trigger | 单击 | 手势 |
| `doubleTap` | Trigger | 双击 | 手势 |
| `grab` | Trigger | 被拎起 | 长按 |
| `eat` | Trigger | 喂食 | 互动 |
| `play` | Trigger | 玩耍 | 互动 |
| `train` | Trigger | 训练 | 互动 |
| `levelUp` | Trigger | 升级 | 经验满 |
| `pair` | Trigger | **配对**（替代 `marry`） | 社交 |
| `breed` | Trigger | 生育 | 社交 |
| `deityReveal` | Trigger | ⭐ 神兽形态揭晓（v2.1） | 稀有事件 |
| `mutantReveal` | Trigger | ⭐ 异兽诞生揭晓（v2.1） | 稀有事件 |

### 4.3 基因输入（决定外观差异）

| 输入名 | 类型 | 范围 | 影响 |
|--------|------|------|------|
| `geneBodySize` | Number | 0~1 | 体型缩放 |
| `geneHueShift` | Number | 0~1 | 色相偏移 |
| `genePatternDensity` | Number | 0~1 | 花纹密度/透明度 |
| `geneEyeSize` | Number | 0~1 | 眼睛缩放 |
| `geneTailLength` | Number | 0~1 | 尾巴长度/摆幅 |
| `liveliness` | Number | 0~1 | 待机动作频率 |

> 💡 **这是"每只宠物都不同"的关键**。美术需把这些输入连到对应的骨骼/变形参数上。

### 4.3.1 稀有度与形态输入（⭐ v2.1 新增）

> **重要**：稀有度**不换模型**，神兽形态**不重做骨骼**。全部靠输入通道驱动。
> 详见 §2.3 资源组织策略。

| 输入名 | 类型 | 范围 | 影响 |
|--------|------|------|------|
| `rarityTier` | Number | 0~5 | 光效强度 / 描边颜色档位（5=异兽） |
| `isMutant` | Boolean | — | ⭐ 开启**异变层**（异色瞳 / 荧光 / 双色 / 变异体型） |
| `hasDeity` | Boolean | — | ⭐ 开启**神兽附加层** |
| `deityId` | Number | 0~3 | 0=凤凰 1=麒麟 2=蛟龙 3=神龟（**蠃虫不设神兽形态，恒不传此值**，见 ADR-020） |

**设计意图**

- 稀有度是「**同一只宠物更闪/更贵**」，不是「换了一只」→ 高稀有度只加特效层
- 异兽是「**同一只物种发生异变**」，不是新物种 → 复用骨骼，只叠异变层
- 神兽形态是「**五虫之长**」的具象化 → 复用基础骨骼 + 部件层（翅膀/角/尾/光环）
- 这样美术成本从"物种 × 稀有度 × 形态"的乘积爆炸，收敛为**加法**（18 骨骼 + 5 附加层）

### 4.4 动画状态清单（最少需交付）

| 状态 | 循环方式 | 时长建议 | 优先级 |
|------|---------|---------|-------|
| Idle | Loop | 3~5s | P0 |
| Blink（可并入 Idle） | Loop | — | P0 |
| Tap 反应 | Once | 0.6s | P0 |
| DoubleTap 兴奋 | Once | 1.2s | P0 |
| Grab 被拎起 | Loop（按住时） | — | P1 |
| Eat 进食 | Once | 2s | P1 |
| Play 玩耍 | Once | 2.5s | P1 |
| Train 训练 | Once | 3s | P1 |
| Tired 疲倦 | Loop | 2s | P1 |
| Sleepy 打哈欠 | Once | 1.5s | P1 |
| Sleeping 睡着 | Loop | 4s | P1 |
| LevelUp 升级 | Once | 2s | P1 |
| Focusing 专注陪伴 | Loop | 4s | P2 |
| Upset 低心情 | Loop | 3s | P2 |
| **Pair 配对** | Once | 4s | P2 |
| **Breed 生育** | Once | 4s | P2 |

**蛋阶段单独一套**（`pet_egg.riv`）：

| 状态 | 说明 |
|------|------|
| Incubating | 随 `hatchProgress` 晃动幅度增大 |
| Hatching | 裂纹→碎裂→探头（3s） |

**神兽/异兽揭晓（v2.1 独有，跨物种复用）**

| 状态 | 说明 |
|------|------|
| DeityReveal | 基础形态 → 附加层逐个显现（翅膀展开/光环点亮），配特效，2~3s |
| MutantReveal | 异变层"侵蚀式"显现（颜色由中心扩散、瞳孔变色），1.5~2s |

> 这两段是**长线目标的情绪高潮**（见 06 §7 S4），值得单独做，且只需两段即可覆盖所有物种。

### 5.2 资源解析器

```kotlin
// app/pet/renderer/PetAssetResolver.kt
object PetAssetResolver {

    fun resolve(species: PetSpecies, stage: PetStage): Int {
        // 先找精确匹配
        val exact = "${species.id}_${stage.name.lowercase()}"
        ResourceLoader.raw(exact)?.let { return it }

        // 降级：如 elder 复用 adult
        val fallback = fallbackStage(stage)
        ResourceLoader.raw("${species.id}_${fallback.name.lowercase()}")?.let { return it }

        // 最终兜底
        return R.raw.pet_sprout_chicken_baby
    }

    /** 阶段资源复用规则：长者沿用成年模型 */
    private fun fallbackStage(stage: PetStage): PetStage = when (stage) {
        PetStage.ELDER -> PetStage.ADULT
        PetStage.HATCHING -> PetStage.BABY
        else -> PetStage.BABY
    }
}
```

**好处**：美术未交付长者资源时，自动复用成年模型，**不阻塞开发**。

### 5.3 体积控制

| 按需下载 | 高端种族资源放 CDN，首次使用该种族时下载 |

## 八、Phase 1 过渡方案（Rive 资源未就绪时）

**不要因为等美术而停工**。先做"增强版帧动画 + 属性动画"，实现基本互动：

```kotlin
class FramePetRenderer(private val imageView: ImageView) : PetRenderer {

    override fun render(state: PetRenderState) {
        when (state) {
            is PetRenderState.Petted -> {
                imageView.setImageResource(R.drawable.pet_happy)
                bounce()                       // 属性动画：跳跃 + 挤压回弹
            }
            is PetRenderState.Grabbed -> {
                imageView.setImageResource(R.drawable.pet_grabbed)
                stretchVertically()            // 纵向拉伸模拟"被拎起"
            }
            is PetRenderState.Sleeping -> imageView.setImageResource(R.drawable.pet_sleep)
            else -> imageView.setImageResource(R.drawable.pet_idle)
        }
    }

    /** 挤压回弹：立体感的关键 */
    private fun bounce() {
        imageView.animate().scaleX(1.15f).scaleY(0.88f).setDuration(110)
            .withEndAction {
                imageView.animate().scaleX(0.95f).scaleY(1.06f).setDuration(140)
                    .withEndAction {
                        imageView.animate().scaleX(1f).scaleY(1f).setDuration(100).start()
                    }.start()
            }.start()
    }

    private fun stretchVertically() {
        imageView.animate().scaleX(0.82f).scaleY(1.35f).setDuration(160).start()
    }
}
```

**这只鸟也能"活"**：配合随机待机定时器 + 触摸监听，体验已远超现状。
